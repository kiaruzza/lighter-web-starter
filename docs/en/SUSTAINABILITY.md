# Sustainability: decisions you can explain and verify

**English** | [Italiano](../SOSTENIBILITA.md)

## Starting point

The template provides static output, system fonts, no initial JavaScript, local
resources and per-page budgets. These choices support the team's work; they do
not automatically assign an EcoIndex grade or WSG conformance to your site.

The [WSG, W3C draft of 16 October 2026](https://www.w3.org/TR/2026/DNOTE-web-sustainability-guidelines-20261016/)
provide a review reference. The toolkit handbook includes an agenda and record
connecting official criteria, evidence, actions and owners.

## Decisions your project still needs

| Decision | Suggested evidence to keep |
| --- | --- |
| Which need does each page address? | Objective, journey and editorial review |
| Which media are necessary? | Variants, visual comparison and Network |
| Is an external service needed? | Activation, cost, data and alternatives |
| Who provides hosting? | Plan, domain and dated documents |
| How is the site maintained? | Owners, deadlines and artifact retention |
| Which results should be published? | Method, conditions, reports and limitations |

## EcoIndex and a technical page

Analyze your own domain, check the observed page and keep the URL, date,
version, weight, requests and DOM. Separate these inputs from the service's
indicators and estimates. The toolkit imports existing results without starting
new scans. Do not copy the original site's score.

If you create an “About this site” page, describe concrete choices, automated
and manual checks, unresolved issues and the update date. For environmental
estimates, name the model, boundaries and assumptions; do not present build
bytes as energy.

## Hosting and carbon.txt

Check your domain with Green Web Check and collect documents relevant to the
service. To publish carbon.txt, use the [builder and validator](https://carbontxt.org/tools)
with your own providers. The template has no prefilled claims that could
attribute another site's evidence to your project.
